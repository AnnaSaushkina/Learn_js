### Артефакт А — `TaskItem.tsx`

**Концепции:** useState, props, условный рендеринг, .map(), события

```tsx
// Типизированные props — контракт между компонентами
interface TaskItemProps {
  task: Task;
  onDelete: (id: string) => void;
  onToggle: (id: string) => void;
  onOpen: (task: Task) => void;
}

export default function TaskItem({
  task,
  onDelete,
  onToggle,
  onOpen,
}: TaskItemProps) {
  // useState: локальное UI-состояние (не нужно нигде кроме этого компонента)
  const [hovered, setHovered] = useState(false);

  const isDone = task.completed;
  const taskStatus = task.status ?? 'свободно';

  // .map() — рендеринг динамического списка тегов
  const tags = [
    task.ticketNumber && <Tag key="ticket">#{task.ticketNumber}</Tag>,
    !isDone && taskStatus === 'свободно' && (
      <Tag key="status" color="success">
        🟢 Можно взять
      </Tag>
    ),
    !isDone && taskStatus === 'в_работе' && (
      <Tag key="status" color="processing">
        🔵 В работе
      </Tag>
    ),
    !isDone && taskStatus === 'тестирование' && (
      <Tag key="status" color="purple">
        ✅ Тестируется
      </Tag>
    ),
    task.deadline && (
      <Tag key="deadline" color={getDeadlineColor(task.deadline)}>
        ⏰ {formatDeadline(task.deadline)}
      </Tag>
    ),
  ].filter(Boolean); // убираем false/null

  // Обработчик события с остановкой всплытия
  const handleToggle = (e?: React.MouseEvent) => {
    e?.stopPropagation(); // клик не должен дойти до родителя (onOpen)
    onToggle(task.id); // вызываем prop-функцию родителя
  };

  return (
    <div
      style={{
        borderLeft: `3px solid ${STATUS_BORDER[taskStatus]}`,
        transform: hovered ? 'scale(1.005)' : 'scale(1)', // условный стиль
        opacity: isWaiting && !isDone ? 0.5 : 1,
      }}
    >
      <div
        onClick={() => onOpen(task)}
        onMouseEnter={() => setHovered(true)} // событие → setState
        onMouseLeave={() => setHovered(false)}
      >
        {/* УСЛОВНЫЙ РЕНДЕРИНГ: два разных вида в зависимости от isDone */}
        {isDone ? (
          <Text>{task.ticketNumber || task.title}</Text>
        ) : (
          <>
            <Text>{task.title}</Text>
            <div>{tags}</div>

            {/* Условный рендеринг скриншотов */}
            {task.screenshots?.length > 0 &&
              task.screenshots
                .slice(0, 3)
                .map((src, i) => (
                  <img key={i} src={src} style={{ width: 68, height: 68 }} />
                ))}
          </>
        )}
      </div>
    </div>
  );
}
```

**Что демонстрирует:**

- `useState` — хранение hover-состояния, влияющего только на вёрстку
- **Props** — компонент получает данные и функции от родителя, ничего не знает об API
- **Условный рендеринг** — `isDone ? ... : ...` и `condition && <JSX>`
- **`.map()`** — список тегов строится динамически из массива
- **События** — `onMouseEnter/Leave` → setState, `onClick` → prop-функция, `stopPropagation`

### Артефакт Б — `TaskForm.tsx`

**Концепции:** управляемые формы, useRef, props-callback, бизнес-логика в обработчике

```tsx
interface TaskFormProps {
  values: TaskFormValues; // данные живут в родителе
  onChange: (values: TaskFormValues) => void; // форма сообщает об изменениях
  errors?: Partial<Record<keyof TaskFormValues, string>>;
}

export default function TaskForm({ values, onChange, errors }: TaskFormProps) {
  const [managerOpen, setManagerOpen] = useState(false);

  // useRef: нужен прямой доступ к DOM-элементу (скрытый input)
  const fileInputRef = useRef<HTMLInputElement>(null);

  // Один универсальный обработчик вместо отдельного на каждое поле
  const update = (field: keyof TaskFormValues, value: unknown) => {
    onChange({ ...values, [field]: value }); // иммутабельное обновление + уведомление родителя
  };

  return (
    <div>
      {/* УПРАВЛЯЕМЫЙ INPUT: value из props, изменение через onChange */}
      <Input
        value={values.title}
        onChange={(e) => update('title', e.target.value)}
        status={errors?.title ? 'error' : undefined} // условное отображение ошибки
      />
      {errors?.title && <Text>{errors.title}</Text>}{' '}
      {/* условный рендеринг ошибки */}
      {/* Дедлайн с бизнес-логикой: если срок ≤ 1 день → авто high priority */}
      <DatePicker
        value={values.deadline}
        onChange={(val) => {
          const updates: Partial<TaskFormValues> = { deadline: val };
          if (val && val.valueOf() - Date.now() <= 24 * 60 * 60 * 1000) {
            updates.priority = 'high'; // один ивент меняет сразу два поля
          }
          onChange({ ...values, ...updates });
        }}
      />
      {/* useRef для программного открытия скрытого file input */}
      <Button onClick={() => fileInputRef.current?.click()}>
        Загрузить файл
      </Button>
      <input
        ref={fileInputRef}
        type="file"
        accept="image/*,.heic,.heif"
        multiple
        style={{ display: 'none' }} // скрыт, открывается через ref
        onChange={handleFileUpload}
      />
      {/* .map() для галереи загруженных скриншотов */}
      {values.screenshots.map((src, i) => (
        <div key={i}>
          <img src={src} style={{ width: 100, height: 100 }} />
          <button
            onClick={() =>
              update(
                'screenshots',
                values.screenshots.filter((_, idx) => idx !== i),
              )
            }
          >
            ✕
          </button>
        </div>
      ))}
    </div>
  );
}
```

**Что демонстрирует:**

- **Управляемая форма** — `value` всегда из props, форма не хранит данные сама
- **props-callback паттерн** — форма «поднимает состояние» через `onChange` в родителя
- **`useRef`** — доступ к DOM (программный `click()` на скрытый input)
- **Бизнес-логика в обработчике** — один `onChange` меняет два поля сразу
- **`.map()` с `key`** — список скриншотов, удаление по индексу через `filter`

### Артефакт В — `AssigneesContext.tsx`

**Концепции:** Context API, кастомный хук, useCallback, персистентность

```tsx
// 1. Создаём контекст с типом
const Ctx = createContext<AssigneesCtx | null>(null);

// 2. Provider — компонент-обёртка, который хранит состояние
export function AssigneesProvider({ children }: { children: ReactNode }) {
  // Начальное значение — из localStorage (функциональная инициализация)
  const [assignees, setAssignees] = useState<string[]>(load);

  // useCallback — функции не пересоздаются при каждом рендере
  const add = useCallback((name: string) => {
    const trimmed = name.trim();
    if (!trimmed) return;
    setAssignees((prev) => {
      // функциональное обновление state
      if (prev.includes(trimmed)) return prev; // защита от дублей
      const next = [...prev, trimmed]; // иммутабельно
      localStorage.setItem(STORAGE_KEY, JSON.stringify(next)); // синхронизация
      return next;
    });
  }, []);

  const remove = useCallback((name: string) => {
    setAssignees((prev) => {
      const next = prev.filter((a) => a !== name);
      localStorage.setItem(STORAGE_KEY, JSON.stringify(next));
      return next;
    });
  }, []);

  // 3. Provider передаёт значение всем потомкам
  return (
    <Ctx.Provider value={{ assignees, add, rename, remove }}>
      {children}
    </Ctx.Provider>
  );
}

// 4. Кастомный хук — скрывает useContext и проверяет корректность использования
export function useAssignees(): AssigneesCtx {
  const ctx = useContext(Ctx);
  if (!ctx)
    throw new Error('useAssignees must be used within AssigneesProvider');
  return ctx;
}
```

**Что демонстрирует:**

- **Context API** — создание, Provider, потребление через `useContext`
- **Кастомный хук** — `useAssignees()` как удобная обёртка с защитой от ошибок
- **Функциональное обновление state** — `setAssignees(prev => ...)` для актуального `prev`
- **`useCallback`** — мемоизация функций (не пересоздаются на каждый рендер)
- **Персистентность** — синхронизация React state и localStorage

## 3. Шпаргалка по концепциям

### useState

Хранит локальное состояние компонента. При изменении — перерендер.

```tsx
const [hovered, setHovered] = useState(false);
// → TaskItem: hover-эффект при наведении мыши
```

### Props

Данные, которые родитель передаёт дочернему компоненту. Только вниз.
Функции в props — способ сообщить родителю об изменениях («поднятие состояния»).

```tsx
// TaskItem получает task и onDelete от AppLayout — сам к API не ходит
<TaskItem task={task} onDelete={(id) => dispatch(deleteTask(id))} />
```

### Условный рендеринг

```tsx
{
  isDone ? <CompactView /> : <FullView />;
} // тернарный оператор
{
  task.screenshots?.length > 0 && <Gallery />;
} // && — «показать если»
borderLeft: isDone ? 'none' : `3px solid ${STATUS_BORDER[taskStatus]}`; // условный стиль
```

### Рендеринг списков `.map()`

```tsx
// Правило: у каждого элемента должен быть уникальный key
{
  tasks.map((task) => <TaskItem key={task.id} task={task} />);
}
```

`key` нужен React для эффективного обновления DOM — без него перерисовывается всё.

### Управляемые формы

```tsx
// Компонент не хранит значение сам — оно живёт в state родителя
<Input
  value={values.title} // ← берём из state
  onChange={(e) => update('title', e.target.value)} // ← пишем в state
/>
```

### useRef

Прямой доступ к DOM-узлу. В отличие от state — изменение ref **не вызывает перерендер**.

```tsx
const fileInputRef = useRef<HTMLInputElement>(null);
fileInputRef.current?.click(); // программно нажать на скрытый input
```

### useEffect

Побочные эффекты: запросы к API, подписки, работа с DOM.

```tsx
useEffect(() => {
  dispatch(fetchTasks()); // загружаем данные один раз при монтировании
}, [dispatch]); // [] означает "только при монтировании"
```

### Context API

Данные, доступные любому компоненту в дереве без «пробрасывания» через props.

```tsx
// main.tsx: оборачиваем всё приложение
<AssigneesProvider>
  <App />
</AssigneesProvider>;

// В любом дочернем компоненте:
const { assignees, add } = useAssignees();
```

## 4. Вопросы

**В1: Зачем в `.map()` нужен `key`? Что будет без него?**

`key` — подсказка React, какой элемент в списке изменился. Без него React не может определить что удалить/обновить и перерисовывает весь список. В моём коде у каждого `<TaskItem>` есть `key={task.id}` — уникальный идентификатор из базы данных.

---

**В2: Чем отличается управляемый input от неуправляемого?**

Управляемый — `value` всегда из React state, каждое изменение через `onChange`. React является единственным источником правды. В `TaskForm` все поля управляемые. Неуправляемый — значение живёт в DOM, читается через `ref`. В моём коде неуправляемый только скрытый `<input type="file">` — к нему нет смысла привязывать state.

---

**В3: Зачем вызываешь `e.stopPropagation()` в обработчиках?**

Карточка задачи кликабельна целиком (`onClick={() => onOpen(task)}`), но кнопки внутри — «Выполнено» и «Удалить» — имеют свои обработчики. Без `stopPropagation()` клик по кнопке всплывал бы до родителя и открывал карточку одновременно с удалением.

---

**В4: Зачем здесь Context, а не просто props?**

Список исполнителей нужен сразу в трёх местах: `TaskForm`, `TaskCard` и `AssigneeManager`. Передавать его через props пришлось бы через `AppLayout → TaskEditor → TaskForm` (prop drilling). Context позволяет любому компоненту получить данные напрямую через `useAssignees()`.

---

**В5: Почему функции `add` и `remove` обёрнуты в `useCallback`?**

Без `useCallback` каждый рендер `AssigneesProvider` создавал бы новые объекты функций. Это заставляло бы перерисовываться все компоненты-потребители. `useCallback` возвращает ту же ссылку — компоненты не перерисовываются без необходимости.

---

**В6: Зачем `useRef` в `useTaskSound`, если там нет DOM?**

`useRef` хранит любое значение, которое не должно вызывать перерендер при изменении. В `useTaskSound` нужно помнить предыдущий список задач между рендерами — это идеальный случай для `ref`. Если бы использовала `useState`, каждое сохранение предыдущего списка вызывало бы лишний рендер.

---

**В7: Что такое «поднятие состояния» и где ты его применяешь?**

Когда несколько компонентов работают с одними данными, состояние переносится в их общего родителя. `TaskForm` — «глупый» компонент, он не хранит данные формы. Данные хранятся в `TaskEditor` (родителе), который передаёт `values` вниз и слушает `onChange`. Форма только сообщает: «пользователь что-то изменил».
